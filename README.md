# 이평선 히스테리시스 시그널 봇

GitHub Actions에서 매일 아침 자동으로 돌면서, 25개 종목의 **목표 보유 비중**을 계산해 텔레그램으로 보내주는 봇입니다. 서버가 필요 없고 무료입니다.

---

## 전략

### 1) 상태 판정 — 히스테리시스

종목마다 **20 / 60 / 120 / 200일선** 각각에 대해 ON/OFF 상태를 추적합니다.

| 현재 상태 | 전환 조건 |
|---|---|
| OFF → **ON** | 종가 > `MA × 1.03` **그리고** 당일 상승 |
| ON → **OFF** | 종가 < `MA × 0.98` **그리고** 당일 하락 |
| 그 외 | 전일 상태 유지 |

핵심은 **진입 문턱(+3%)과 이탈 문턱(-2%)이 다르다**는 점입니다. 그 사이 5% 구간에서는 아무 일도 일어나지 않습니다. 전기회로의 슈미트 트리거와 같은 구조로, 이평선 근처를 오르내릴 때 매매 신호가 반복해서 뜨는 **휩소(whipsaw)를 구조적으로 억제**합니다.

`CONFIRM_DIRECTION = True`이면 상태가 **바뀌는 순간에만** 당일 등락 방향을 확인합니다. 밴드를 뚫었는데 방향이 안 맞으면 전환이 보류되고, 다음 날 조건이 다시 충족되면 그때 전환됩니다. 신호가 영영 사라지지 않습니다.

### 2) 포지션 비중

ON된 이평선 개수에 따라 **종목별로 독립 산정**합니다.

| ON 개수 | 목표 비중 |
|---|---|
| 4개 (●●●●) | **100%** |
| 3개 (●●●○) | **75%** |
| 2개 (●●○○) | **50%** |
| 1개 (●○○○) | **25%** |
| 0개 (○○○○) | **0%** |

여기서 100%는 "그 종목에 배정하기로 한 금액의 100%"라는 뜻입니다. 종목 간 배분 비율은 봇이 정하지 않으니 직접 정하셔야 합니다.

## 설치 순서

### 1단계 — 텔레그램 봇 만들기

1. 텔레그램에서 **[@BotFather](https://t.me/BotFather)** 검색 → 대화 시작
2. `/newbot` 입력
3. 봇 이름 입력 (아무거나)
4. 봇 사용자명 입력 — 반드시 **`bot`으로 끝나야** 합니다 (예: `my_ma_signal_bot`)
5. 발급된 **토큰**을 복사 (`1234567890:AAHdqTcv...` 형태)

### 2단계 — chat_id 알아내기

1. 만든 봇과 대화창을 열고 **`/start`** 전송 (이 단계를 건너뛰면 봇이 먼저 말을 걸 수 없습니다)
2. 브라우저에서 아래 주소를 엽니다

   ```
   https://api.telegram.org/bot<토큰>/getUpdates
   ```

3. 응답에서 `"chat":{"id":123456789` 의 숫자가 **chat_id** 입니다

> `{"ok":true,"result":[]}` 로 비어 있으면 1번을 안 한 것입니다.

### 3단계 — GitHub 저장소

**Private** 저장소를 만들고 파일을 올립니다.

```bash
git init
git add .
git commit -m "init"
git branch -M main
git remote add origin https://github.com/<사용자명>/<저장소명>.git
git push -u origin main
```

> Private이어도 무료입니다. 1회 실행 1~2분, 월 26회로 약 50분 — Free 플랜 월 2,000분 안에 들어갑니다.

### 4단계 — Secrets 등록

저장소 → **Settings** → **Secrets and variables** → **Actions** → **New repository secret**

| 이름 | 값 |
|---|---|
| `TELEGRAM_BOT_TOKEN` | 1단계 토큰 |
| `TELEGRAM_CHAT_ID` | 2단계 숫자 |

### 5단계 — 테스트

**Actions** 탭 → **MA Signal** → **Run workflow**

## 실행 시각

cron은 **UTC 기준**입니다. 현재 `15 20 * * 0-5` = UTC 일~금 20:15 = **KST 월~토 05:15**.

05:30이 아니라 05:15인 이유는 GitHub 예약 실행이 **5~20분 지연**되는 경우가 흔해서입니다. 정시 실행은 보장되지 않습니다.

**KST → UTC는 9시간을 빼면 됩니다.**

## 커스터마이징

`ma_signal.py` 상단에서 조정합니다.

```python
BAND_UP = 1.03            # 매수 문턱 (+3%)
BAND_DN = 0.98            # 매도 문턱 (-2%)
MA_PERIODS = [20, 60, 120, 200]
SCALAR_MAP = {4: 1.00, 3: 0.75, 2: 0.50, 1: 0.25, 0: 0.00}
CONFIRM_DIRECTION = True  # False면 방향 확인 없이 밴드만으로 전환
```

종목 추가는 `TICKERS`에. 코스피는 `.KS`, 코스닥은 `.KQ`, 미국은 접미사 없음.

`signal.yml`에서 `ALWAYS_SEND: "false"`로 바꾸면 **비중 변동이 있을 때만** 알림이 옵니다.

## 문제 해결

| 증상 | 원인 / 해결 |
|---|---|
| 알림이 안 옴 | Secrets 이름 오타 확인 (대소문자 포함) |
| `chat not found` | chat_id 오류 또는 봇에게 `/start` 미전송 |
| 특정 종목 "데이터 부족" | 상장 230일 미만. 200일선 + 워밍업 불가 |
| 특정 종목 "데이터 없음" | 티커 오류이거나 Yahoo 미지원 |
| 며칠째 실행 안 됨 | Actions 탭에서 워크플로 비활성화 여부 확인 |

### 알아둘 점

- **yfinance는 Yahoo Finance의 비공식 API**입니다. 데이터센터 IP는 간헐적으로 차단될 수 있고, Yahoo가 사양을 바꾸면 예고 없이 깨집니다. 4회 재시도를 넣었지만 근본 해결은 아닙니다.
- **미국/한국 종목을 나눠서 받습니다.** 거래일이 달라 함께 받으면 공통 거래일만 남아 데이터가 크게 잘리기 때문입니다.
- **수정주가(auto_adjust) 기준**이라 증권사 HTS 화면의 숫자와 다를 수 있습니다.
- **60일 자동 중지**: `keepalive.yml`이 매월 1일·21일 빈 커밋으로 방지합니다.
- **워밍업 구간**: 히스테리시스는 과거 상태가 누적돼야 정확합니다. 3년치를 받아 200일선 이후부터 상태를 굴리므로, 실제 판정에 쓰이는 구간은 약 2년입니다.

## 면책

이 도구는 **정해진 규칙을 기계적으로 계산해 알려줄 뿐이며, 투자 권유가 아닙니다.**

특히 다음을 유의하세요.

- **밴드 수치(+3%/-2%)의 근거가 약합니다.** 참고한 자료에서는 QQQ/TLT/GLD 3자산에 대해 10년 백테스트로 최적화한 값이었습니다. 여기 25개 종목에는 검증된 바 없이 그대로 옮겨온 숫자입니다.
- **최적화된 파라미터는 과최적화(overfitting)를 의심해야 합니다.** 과거에 가장 잘 맞았던 값이 미래에도 맞으리라는 보장은 없습니다. 조정하실 경우 학습 구간과 검증 구간을 나눠(out-of-sample) 확인하세요.
- **손절·익절 규칙이 없습니다.** 비중 스케일링이 완만한 축소 역할을 하지만 손절과는 다릅니다.
- **종목 분산이 아닙니다.** 25개 중 상당수가 반도체·AI 관련주라 하락장에서 동시에 비중이 줄어들 가능성이 높습니다.

**실제 자금을 넣기 전에 반드시 과거 데이터로 백테스트**하시고, 모든 투자 판단과 결과에 대한 책임은 이용자 본인에게 있습니다.
