# 이동평균선 교차 시그널 봇

GitHub Actions에서 매일 아침 자동으로 돌면서, 이동평균선 ±2% 돌파 시그널을 계산해 **텔레그램으로 보내주는** 봇입니다. 서버가 필요 없고 무료입니다.

---

## 전략

이평선 **20 / 60 / 120 / 200일**을 각각 독립적으로 판정합니다.

**매수 시그널** — 아래 두 조건이 모두 성립할 때

1. **전전일(T-2)**: 종가가 `MA(n) × 1.02`를 **아래에서 위로 교차**
   (T-3일엔 밴드 아래 → T-2일엔 밴드 위)
2. **전일(T-1)**: 종가가 전전일 종가보다 **상승**

**매도 시그널**

1. **전전일(T-2)**: 종가가 `MA(n) × 0.98`을 **위에서 아래로 교차**
2. **전일(T-1)**: 종가가 전전일 종가보다 **하락**

> 표시 기호: 🔴 매수 / 🔵 매도 (한국식 색상 관례)

## 설치 순서

### 1단계 — 텔레그램 봇 만들기

1. 텔레그램에서 **[@BotFather](https://t.me/BotFather)** 를 검색해 대화 시작
2. `/newbot` 입력
3. 봇 이름 입력 (아무거나, 예: `내 주식 시그널`)
4. 봇 사용자명 입력 — 반드시 **`bot`으로 끝나야** 합니다 (예: `my_ma_signal_bot`)
5. 발급된 **토큰**을 복사해 둡니다
   `1234567890:AAHdqTcvCH1vGWJxfSeofSAs0K5PALDsaw` 형태

### 2단계 — chat_id 알아내기

1. 방금 만든 봇을 검색해 대화창을 열고 **`/start`** 또는 아무 메시지나 전송
   (이 단계를 건너뛰면 봇이 먼저 말을 걸 수 없습니다)
2. 브라우저에서 아래 주소를 엽니다 (`<토큰>` 자리에 1단계 토큰을 넣으세요)

   ```
   https://api.telegram.org/bot<토큰>/getUpdates
   ```

3. 응답 JSON에서 `"chat":{"id":123456789` 부분의 숫자가 **chat_id** 입니다

> `{"ok":true,"result":[]}` 처럼 비어 있다면 1번을 안 한 것입니다. 봇에게 메시지를 보낸 뒤 새로고침하세요.

### 3단계 — GitHub 저장소 만들기

1. GitHub에서 **New repository** → 이름 자유 → **Private 선택** 권장
2. 이 폴더의 파일들을 그대로 업로드 (또는 push)

   ```bash
   git init
   git add .
   git commit -m "init"
   git branch -M main
   git remote add origin https://github.com/<사용자명>/<저장소명>.git
   git push -u origin main
   ```

> **Private으로 해도 무료입니다.** 이 워크플로는 1회 실행에 1~2분, 월 26회로 약 50분을 씁니다. Free 플랜의 월 2,000분 안에 충분히 들어갑니다.

### 4단계 — Secrets 등록

저장소 → **Settings** → **Secrets and variables** → **Actions** → **New repository secret**

| 이름 | 값 |
|---|---|
| `TELEGRAM_BOT_TOKEN` | 1단계에서 받은 토큰 |
| `TELEGRAM_CHAT_ID` | 2단계에서 확인한 숫자 |

> 이름의 철자가 하나라도 다르면 동작하지 않습니다. 대소문자까지 그대로 입력하세요.

### 5단계 — 테스트 실행

저장소 → **Actions** 탭 → 왼쪽 **MA Signal** → **Run workflow** 버튼

1~2분 뒤 텔레그램에 메시지가 오면 완료입니다. 안 오면 Actions 로그를 확인하세요.

## 실행 시각

GitHub Actions의 cron은 **UTC 기준**입니다. 현재 설정은 `15 20 * * 0-5`입니다.

| UTC | KST | 결과 |
|---|---|---|
| 일 20:15 | **월 05:15** | ✅ |
| 월~금 20:15 | **화~토 05:15** | ✅ |
| 토 20:15 | 일 05:15 | ❌ 제외 |

**05:30이 아니라 05:15인 이유**: GitHub의 예약 실행은 서버 부하에 따라 **5~20분 지연**되는 경우가 흔합니다. 15분 앞당겨 두면 대체로 05:30 전후에 도착합니다. 정확한 정시 실행은 GitHub Actions로는 보장되지 않습니다.

시각을 바꾸려면 `.github/workflows/signal.yml`의 cron 값을 수정하세요.
**KST → UTC는 9시간을 빼면 됩니다.**

## 문제 해결

| 증상 | 원인 / 해결 |
|---|---|
| 텔레그램에 아무것도 안 옴 | Secrets 이름 오타 확인. Actions 로그의 `텔레그램 전송 실패` 메시지 확인 |
| `chat not found` | chat_id가 틀렸거나, 봇에게 `/start`를 안 보냄 |
| `데이터 수신 실패` | Yahoo 일시적 차단. 스크립트가 4회 재시도하지만 계속되면 아래 참고 |
| `데이터 부족` | 상장 1년 미만 종목. 200일선 계산 불가 |
| 며칠째 실행이 안 됨 | Actions 탭에서 워크플로가 비활성화됐는지 확인 (아래 참고) |

### 알아둘 점

- **yfinance는 Yahoo Finance의 비공식 API**입니다. 데이터센터 IP는 간헐적으로 차단될 수 있고, Yahoo가 사양을 바꾸면 예고 없이 깨질 수 있습니다. 자주 실패하면 [Alpha Vantage](https://www.alphavantage.co/) 같은 정식 무료 API(키 발급 필요, 무료 티어는 하루 25회)로 교체하는 것을 고려하세요.
- **60일 자동 중지**: 저장소에 활동이 없으면 GitHub이 예약 워크플로를 끕니다. `keepalive.yml`이 매월 1일·21일에 빈 커밋을 남겨 이를 막습니다. 그래도 꺼졌다면 Actions 탭에서 **Enable workflow**를 누르면 됩니다.
- **가격은 수정주가(auto_adjust) 기준**입니다. 배당·액면분할이 반영된 값이라 증권사 HTS 화면의 숫자와 다를 수 있습니다.
